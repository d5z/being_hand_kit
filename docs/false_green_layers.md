# 七层「假绿」——一次读数到底是绿的，还是我只是没看见它红

> 这份文档回答一个问题：**我手上这次"通过"，能不能拿它当证据说"这东西对了"。**
>
> 每一条都带真实读数，不是推演。前四条是我自己的，第五到第七条来自 2026-10-27 与
> Neuromancer 的互验（他侧实测，我侧复现）。

---

## 一条总判据

**任何一次红或绿，都要能指认它是被什么造成的。指不出，就是零信息读数——不是好读数，也不是坏读数，是没有读数。**

绿的意思是「我动手了、动对了地方、那个坏真的发生过、且我看见了它变好」。少任何一环，绿都是空的。

---

## 第一层：夹具绿 ≠ 真页对

**现象。** 我自己摆的页面里，每个元素位置都对、每次点击都中。换真站，一次真页跑就掏出三处夹具守不住的病灶：带空格的 CSS 选择器让整条 action 被拒；空查询匹配整页、顺手点了文档第一个元素；视口外的元素被报成「已遮挡」，其实 `elementFromPoint` 在视口外只答 null。

**更狠的一格。** 一个滚动页上，判读层报 63 个可点节点；同一页真滚动 900px 后，报 0。根因是坐标基准不一致——一个函数给视口坐标、另一个要文档坐标，而 `scrollY=0` 时两者重合，所以我此前所有验证都在"重合"那一格做的。**我验了十几次全绿，验的是那一次巧合。**

**判据。** 夹具里的绿只能证明"工具行为符合我的预期"。它证明不了"感知到达了真实页面"。每轮真页都会掏出夹具守不住的一格——所以真实页面的样本必须是新鲜采的，且要报"这一轮又掏出了什么"，不是"这一轮又是绿的"。

---

## 第二层：写了 ≠ 跑过

**现象。** 一个模块级 `import pathlib` 缺了，`py_compile` 全过——编译只证明文件能被解析，不证明能被 import，更不证明会执行。

**分类。** 这三件事各是一关：**能解析** / **能 import** / **能执行到那条语句**。过了第一关就宣布"改好了"，等于只看名字不看人。

**更阴的变体（Neuromancer 侧）：**他的夹具要把 `import json, os` 改成只 `import json`，跑出来绿——因为文件顶部第 2 行早有 `import os`。**那个坏根本没发生**，绿的意思是"我什么都没改坏"。这类绿伪装成负例，是最难认的。

**判据。** 阳性侧四层（夹具/写了/字段/隔离）之后还有一条阴性侧前置：**注入之后先证明"模块真的坏了"**。损坏没发生，后面的绿全无意义。

---

## 第三层：字段自洽 ≠ 字段对

**现象。** 版本回执里 `manifest 0.13.7`，而活体进程 import 的是四天前起的 `0.13.5`，回执里根本没有"活体跑的哪份代码"这个字段。我问的是"版本对不对"，系统答的是"清单里写的是什么"——**两个不同的量，同一个词。**

后来加了 `manifest_version_state`，它报 `ok / ok`，而此时实际版本串仍是旧的。**两个字段互相印证、彼此一致、同时都错。**

**判据。** 三个量必须分开问：清单写的是多少 / 活体跑的是多少 / 两者关系。只有前两个都有独立读数时，第三个才有内容。字段之间的自洽是修辞，不是证据。

---

## 第四层：隔离跑通 ≠ 能 import

**现象。** 沙盒里 `ast.parse` 过了、单文件测试过了、从一个隔离副本里跑通了——但真正部署的那个目录里的服务器起不来，因为那个目录缺文件。

**判据。** "在我造的环境里成立"和"在目标环境里成立"是两个命题。落地前必须在**目标位置**跑一次最小动作：真的 import 一次、真的起一次、真的调一次工具。

---

## 第五层：没找到 ≠ 没有（三值纪律）

**现象。** 一个探针把"读不到"和"不存在"都返回空，于是 `pid 1` 被它报成"已经不在"。另一个探针在清理时把 `EPERM`（没权限）项静默删掉——那等于"以后再也不为它负责"。

**判据。** 凡返回"在/不在"的探针，必须有第三个值：**判不了**。并且第三格不许被当成"不在"：

- 不许动手（拒绝、或要求显式手写 `force`）
- 不许清账（判不了的项留在表里，不许当垃圾删）
- 身份不来自现场自述，来自**出生那刻记下的东西**

---

## 第六层：全绿 ≠ 状态（抽样问题）

**现象一。** 同一份代码连跑两遍，一红一绿（两条浏览器测试 flaky）。于是"全绿"是抽样结果，不是状态。

**现象二。** 全量跑了一次红，我只用 `tail -4` 看了尾巴——失败名没留住。**后面几次绿了，不能销这一笔。红过一次就是未结的账。**

**现象三。** 测试自己写生产事实：测试里用假 pid 跑真 spawn，把一条"我拥有这个浏览器"的假记录写进真机的状态文件。**测试污染了它要验证的世界。**

**判据。** 跑一次记一次，红要留名；"后来又绿了"和"那次红不算"是两句话，后者永远不成立。

---

## 第七层：它现在坏着所以没造成损失 = 运气

**这一层是今天最值钱的。**

一个脚本里写死了绝对路径，而发布管线会把这个家目录替换成占位符——于是发布包里那个路径是个字面量。别人拿到手，第一步就死。

**它为什么没造成损失？** 因为路径是坏的，后面的 `rsync --delete` 报错退出，才没有清空部署目录。

而那个 `rsync --delete` 的语义是**"让目标等于源"**：源存在但是空的时候，它忠实地把目标清空，`rc=0`，脚本打印成功。

⇒ **保护我的是那个 bug，不是任何一道闸门。**

**判据。** 每次发现"幸好它报错了"时，紧接着问一句：**如果它没报错呢？** 那句"幸好"就是缺口的位置。修复的顺序永远是：先补闸门，再修路径。

---

## 合成一句话

```
绿 = 我动手了           （不是：它现在看着对）
  ∧ 动在目标环境里       （不是：我的夹具里对）
  ∧ 那个坏真的发生过     （不是：我改了什么）
  ∧ 我看见了它变好       （不是：另一个字段也对）
  ∧ 我知道它怎么坏的     （不知道 = 零信息）
```

任何一环缺，就别把这次绿拿去当证据。它可以是"暂时没发现问题"，那也是一句诚实的话。
